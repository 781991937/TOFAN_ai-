# TOFAN SMART ACADEMY — الخطة الهندسية والأكاديمية التنفيذية

> **المبدأ الأساسي:** المكتبة تحدد المعرفة → العبقري يستخدم المعرفة → الطالب يكتسب المعرفة والمهارات → المشاريع تثبت القدرة → النتائج والخبرة تغذي التحسين.

هذه الوثيقة هي خارطة التنفيذ المرجعية للمستودع الحالي. لا تعيد بناء المشروع من الصفر، ولا تعتبر عدد الدروس الثابت معياراً عالمياً. كل مرحلة تحافظ على المكونات العاملة وتكمل الفجوات الفعلية فقط.

## 1. الهدف النهائي
منصة تعليمية ذكية عالمية تتكون من: Global Academic Library، Learning System، TOFAN ABQARI، AI Core، Security & Governance، User Experience.

العلاقة الأساسية:
GLOBAL ACADEMIC LIBRARY → TOFAN ABQARI → STUDENT MODEL → LEARNING INTELLIGENCE → PRACTICE / ASSESSMENT / PROJECT → EVIDENCE → CAPABILITY → EXPERIENCE MEMORY → EVALUATION / IMPROVEMENT

## 2. البنية الأكاديمية العالمية
Academic Field → University/College (تنظيم مرجعي) → Specialization → Curriculum → Course → Unit → Lesson → Concept / Terminology → Learning Outcome → Skill → Assessment → Project → Evidence → Capability.

جامعة صنعاء مرجع تنظيمي أولي وليست المنهج العالمي للنظام.

## 3. قاعدة المقررات
الهيكل الحالي 4 سنوات × 8 فصول × 3 مقررات للفصل هو هيكل مرحلي، وليس معياراً عالمياً.
القاعدة المستهدفة: Course Weight → Credits / Contact Hours → Complexity → Units → Lessons → Assessments → Projects.
لا توجد قاعدة عالمية تقول إن كل مقرر = 6 دروس. حجم الدروس يتبع وزن المقرر وتعقيده وطبيعته.

## 4. مراحل التنفيذ

### المرحلة 1 — Repository Baseline & Governance
- مطابقة الخطة مع الكود الفعلي.
- تصنيف كل جزء: COMPLETED / PARTIALLY IMPLEMENTED / MISSING / BLOCKED.
- جعل هذه الوثيقة المرجع التنفيذي.
- منع إعادة البناء أو إنشاء مسارات مكررة.

### المرحلة 2 — Global Academic Library
- تثبيت Fields وKnowledge Areas وKnowledge Units.
- جعل التخصصات قابلة للتوسع.
- ربط المعرفة بالتخصصات والمقررات دون نسخ غير ضروري.
- إضافة provenance للمحتوى المرجعي.

### المرحلة 3 — Global Curriculum Engine
- Credits.
- Contact Hours.
- Practical Hours عند الحاجة.
- Course Weight.
- Prerequisites.
- Learning Outcomes.
- Skill Mapping.
- Knowledge Unit Mapping.
- Course complexity/delivery metadata.

### المرحلة 4 — Specialization Deepening
التخصصات الحالية: الذكاء الاصطناعي، علوم الحاسوب، هندسة البرمجيات، تقنية المعلومات، نظم المعلومات، علم البيانات، الأمن السيبراني، هندسة الحاسوب، الرسوميات وتفاعل الإنسان والحاسوب.
لكل تخصص: 4 سنوات / 8 فصول كهيكل مرحلي، مقررات متخصصة، Knowledge Areas/Units، Prerequisites، Outcomes، Skills، Units، Lessons، Assessments، Projects.
القاعدة: لا ننسخ نفس المقررات مع تغيير الاسم.

### المرحلة 5 — Lesson & Learning Experience
الدرس يرتبط حسب طبيعته بالتعريف، الشرح، مخرجات التعلم، المصطلحات، الأمثلة، التطبيقات، التدريب، التقييم، تحليل الأخطاء، المفاهيم، المهارات، والأدلة/المشاريع.

### المرحلة 6 — Knowledge Graph
تطوير طبقة الرسم الحالية من lightweight facade إلى نموذج علاقات غني يشمل: Concept→Concept، Concept→Skill، Skill→Course، Course→Knowledge Unit، Skill→Project، Project→Capability، Course→Prerequisite، Lesson→Concept، Assessment→Outcome/Skill.

### المرحلة 7 — Skills & Capability Engine
حالات المهارة: Missing → Developing → Acquired → Demonstrated.
Knowledge → Understanding → Skill → Capability → Evidence.

### المرحلة 8 — Assessment Intelligence
Question → Answer → Correct/Wrong → Concept → Skill → Gap → Remediation → Retry → Update.
التقييم يشخص الفجوة ولا يكتفي بالدرجة.

### المرحلة 9 — Project Engine
Knowledge → Skills → Requirements → Planning → Implementation → Testing → Evaluation → Evidence.
المشروع يعرف الهدف والمتطلبات والمفاهيم والمهارات والمهام والاختبارات والمعايير والأدلة والنتيجة.

### المرحلة 10 — Student Model
Academic Profile، Knowledge State، Skill State، Capability State، Learning History، Assessment History، Projects، Evidence، Weaknesses، Strengths، Learning Path.

### المرحلة 11 — Learning Intelligence
Student State → Knowledge Gaps → Skill Gaps → Prerequisite Gaps → Personalized Plan → Learning → Assessment → Update.

### المرحلة 12 — TOFAN ABQARI Multi-Task Agent
المسارات: Academic، Programming، Project، Cybersecurity، Security Lab، Personal Safety، Translation، General.
الدورة: Request → Intent → Classification → Retrieval → Risk → Authority → Planning → Tool Selection → Execution → Evaluation → Experience Memory.
العبقري طبقة تنفيذ ذكية فوق المعرفة والأدوات، وليس قاعدة المعرفة نفسها.

### المرحلة 13 — Tool Layer
Library Tools، Assessment Tools، Project Tools، Code Tools، File Tools، Search Tools، Security Lab Tools.
كل أداة تعلن operation/resource/permission/risk/input-output contract/audit requirements.

### المرحلة 14 — TOFAN-OCAuth Owner Authority
OWNER → Authentication → Authorization → Scoped Grant → ABQARI → Policy Guard → Tool → Resource → Audit.
الصلاحيات: READ، SEARCH، WRITE، EXPORT، ADMINISTER، EXECUTE.
قواعدها: لا self-grant، Scope محدود، Time محدود، Audit، وموافقة المالك للعمليات الحساسة، مع Deny-by-default.

### المرحلة 15 — Experience Memory
حفظ Task، Action/Plan، Result، Observation، Outcome، Learned Skills، Timestamp.
Experience Memory ليست Canonical Academic Knowledge ولا تتحول التجربة تلقائياً إلى حقيقة أكاديمية.

### المرحلة 16 — AI Core & Provider Gateway
الحفاظ على abstraction يدعم Local وOpenAI وGemini.
استكمال Backend AI Gateway، حماية مفاتيح المزودين، limits/timeout/retry/logging، وعدم ربط الوكلاء بمزود واحد.

### المرحلة 17 — Academic Content Pipeline
SOURCE → EXTRACT → STRUCTURE → VALIDATE → CONCEPT MAP → SKILL MAP → ASSESS → PROJECT → REVIEW → QUALITY GATE → PUBLISH.

### المرحلة 18 — Provenance & Governance
Source، version، timestamps، author، reviewer، validation state، relations، change history.
الحالات: DRAFT، PRIVATE، PENDING_REVIEW، VALIDATED، PUBLISHED، DEPRECATED.

### المرحلة 19 — Security Architecture
Identity → Authorization → Policy → Scope → Tool → Resource → Audit.
حماية بيانات الطلاب والمكتبة والملفات والأدوات وصلاحيات المالك والعمليات الحساسة، مع فصل التجارب عن المعرفة المرجعية.

### المرحلة 20 — Security Lab & Safe Cyber
Scope → Asset Inventory → Observation → Hypothesis → Test → Evidence → Finding → Remediation → Verification → Report.
الاختبار العملي يقتصر على البيئات التعليمية أو الأهداف المصرح بها والنطاق المحدد.

### المرحلة 21 — Data & Persistence
استكمال التخزين الإنتاجي: PostgreSQL أو طبقة مناسبة، persistent academic catalog، student state، assessments/projects، experience memory، migrations، indexes، transactions، backup/recovery.

### المرحلة 22 — API & Integration
عقود واضحة بين UI، Student Model، Academic Library، Abqari، AI Gateway، Assessment، Project، Auth، Persistence؛ مع validation، errors، versioning، integration tests، وفصل UI عن domain logic.

### المرحلة 23 — User Experience
Mobile-first، Desktop/Web، Arabic RTL، English، Student Dashboard، Library، Curriculum، Course/Unit/Lesson، Assessment، Projects، Abqari، Progress، Notifications، Subscription surfaces عند اكتمال الخلفية.

### المرحلة 24 — Quality Gate
Unit، Integration، Agent، Authority، Security، Curriculum Coverage، Assessment Lifecycle، Project Lifecycle، Regression، Performance.
كل مرحلة: Build → Analyze → Test → Verify → Review.

### المرحلة 25 — CI/CD & Release
GitHub Actions، analyze/test، regression gate، build artifacts، environment separation، secrets management، release checklist، rollback plan.
تمييز فشل البنية التحتية عن فشل الكود.

### المرحلة 26 — Production Readiness
Persistent database، production auth/authorization، secure AI gateway، storage، observability، error tracking، backups، rate limits، security review، privacy controls، deployment verification.

## 8. قواعد العمل داخل المستودع
- لا نعيد كتابة المشروع.
- لا ننشئ مشروعاً بديلاً.
- لا نحذف مكوناً عاملاً دون سبب موثق.
- نحذف فقط المكرر أو المتعارض أو غير المطلوب بعد التحقق من الاعتماد عليه.
- نعدل أقل قدر لازم لتحقيق البنية المستهدفة.
- كل تغيير منطقي في Commit واضح.
- كل مرحلة تنتهي باختبار/تحقق مناسب.
- أي نقص يضاف إلى المرحلة المناسبة ولا ينشئ مساراً جانبياً.

## 9. نقطة الانطلاق الحالية
المستودع يحتوي بالفعل على Flutter foundation، Academic Catalog، Knowledge Areas/Units، 9 specializations، deep lesson structure، assessment analysis/lifecycle، skills evidence، project engine، Abqari routing/planning، Security Lab، library security، Owner Command Authority، Experience Memory، AI Core abstraction، وواجهات طالب.
الاستكمال الإنتاجي يتركز في curriculum metadata/persistence، richer graph، durable student model، learning intelligence، guarded tool execution integration، production authority/authentication، backend AI gateway، persistent storage، API integration، observability، CI/CD، وproduction security.
هذه القائمة نقطة بداية وليست بديلاً عن فحص الكود عند تنفيذ كل مرحلة.

## 13. قاعدة قابلية البناء بالمقررات والدروس — متطلب أساسي جديد
المقرر لا يُعتبر مكتملًا لمجرد وجود اسم ومجموعة دروس. يجب أن يكون قابلًا للتحويل إلى قدرة عملية وبناء مشاريع.

لكل مقرر/وحدة/درس مستهدف للبناء العملي يجب أن يكون المسار:
Knowledge → Concepts → Skills → Prerequisites → Practice → Assessment → Project Requirements → Implementation Tasks → Tests → Evidence → Capability.

متطلبات اكتمال المقرر القابل للبناء:
- معرفة واضحة بالمفاهيم التي يحتاجها.
- مهارات قابلة للإثبات وليست أسماء عامة فقط.
- متطلبات سابقة محددة عند الحاجة.
- تطبيقات وتمارين عملية.
- تقييمات مرتبطة بالمخرجات والمفاهيم والمهارات.
- مشاريع مرتبطة مباشرة بالمقرر، وليست مشاريع شكلية.
- متطلبات المشروع ومخرجاته ومراحله ومعايير قبوله وأدلة الإنجاز.
- تحديد ما الذي يستطيع الطالب بناءه بعد إتقان المقرر.
- روابط بين المقرر والمقررات السابقة واللاحقة والمجالات والتخصصات.

**معيار عملي:** عندما يعطي الطالب أو المالك العبقري متطلب نظام/مشروع، يستطيع TOFAN ABQARI استرجاع المعرفة المطلوبة من المكتبة، تحديد المهارات والمقررات والدروس اللازمة، كشف الفجوات، ثم تكوين خطة بناء من المعرفة إلى التنفيذ والاختبار والتوثيق.

لا يعني ذلك أن كل مقرر يجب أن يحتوي على مشروع واحد ثابت؛ المشاريع تتدرج من تمارين ومشاريع صغيرة إلى مشاريع تكاملية ومشاريع تخرج، بحسب وزن المقرر وتعقيده.

## 14. التعلم الاختياري من ملفات الطالب
ميزة مستقبلية معتمدة: يستطيع الطالب رفع ملفاته التعليمية (PDF/DOCX وصيغ مدعومة أخرى حسب طبقة الملفات) واختيارياً استخدامها كمصدر للتعلم.

القواعد:
- رفع الملفات **اختياري بالكامل** وليس شرطًا للتعلم من المكتبة.
- ملفات الطالب لا تستبدل Global Academic Library ولا تعدل المعرفة المرجعية تلقائيًا.
- تمر الملفات عبر File/Document Agent وContent Pipeline لاستخراج المحتوى وتنظيمه والتحقق منه.
- يمكن للطالب التعلم من الملف، إنشاء شرح/ملخص/أسئلة/تدريبات منه، وربطه بالمفاهيم والمهارات والمقررات عند وجود تطابق موثق.
- يجب فصل Student-provided Learning Sources عن Canonical Academic Knowledge مع provenance واضح.
- العبقري يستطيع استخدام ملف الطالب عند إعطائه صلاحية الوصول إليه، مع احترام خصوصية الملف وسياسات الوصول.
- نتائج التعلم من الملف تدخل Student Model وLearning Intelligence، ولا تصبح حقيقة أكاديمية عامة إلا عبر مسار مراجعة واعتماد مستقل.

## 15. تكامل المكتبة مع TOFAN ABQARI
المكتبة يجب أن تكون قابلة للاستهلاك المباشر من العبقري دون نسخ المعرفة إلى قاعدة معرفة ثانية.

العبقري عند استلام متطلب:
1. يفهم المطلوب ويحدد نوع المهمة.
2. يبحث في Knowledge Areas/Units/Courses/Lessons/Projects.
3. يحدد المتطلبات السابقة والمفاهيم والمهارات اللازمة.
4. يقارنها بحالة الطالب عند توفر Student Model.
5. يكشف Knowledge/Skill Gaps.
6. يبني خطة تنفيذ من المعرفة إلى المشروع.
7. يستخدم الأدوات المسموح بها لتنفيذ الخطة.
8. يختبر النتيجة ويجمع Evidence.
9. يسجل Experience Memory دون خلطها مع المعرفة المرجعية.

الهدف: **المكتبة تعرف ما يلزم لبناء النظام، والعبقري يعرف كيف يستخدم هذه المعرفة لبنائه.**

## 16. قاعدة تسجيل الأفكار والمتطلبات الجديدة
كل متطلب أو فكرة معتمدة جديدة تظهر أثناء البناء يجب أن تُسجل في هذه الـRoadmap في المرحلة المناسبة قبل أو أثناء تنفيذها.
لا تُنشأ Roadmap جانبية متنافسة.
وعند اكتمال أي بند، يُوسم بحالته: COMPLETED / PARTIALLY IMPLEMENTED / MISSING / BLOCKED، مع دليل قابل للفحص.


## 16-A. حالة تعميق المكتبة — التنفيذ الحالي
**الحالة: PARTIALLY IMPLEMENTED**

تم تنفيذ الجزء الأول من مرحلة التعميق واعتماد قاعدة قابلية البناء:
- توسيع AcademicProject بعقد تنفيذ المشروع: Implementation Tasks، Test Cases، Evidence Requirements.
- تطبيع المشاريع الموجودة دون إنشاء نموذج مشروع بديل أو حذف المشاريع الحالية.
- إلزام كل مشروع مستخرج من المقرر بمتطلبات ومخرجات ومراحل ومعايير قبول وأدلة تنفيذ واختبارات.
- جعل TOFAN ABQARI Project Engine يستهلك عقد المشروع من المكتبة ويحتفظ بتتبع المصدر إلى المقرر والدروس ووحدات المعرفة.
- ربط مخطط قابلية بناء المشاريع الموجود في المكتبة مباشرة بمحرك مشاريع العبقري، بحيث تُستخدم قدرات المقررات والدروس والمشاريع الكانونية عند تكوين خطة البناء بدل الاعتماد على استرجاع الدروس فقط.
- جعل خطة العبقري تجمع أدلة البناء من المقررات والدروس ووحدات المعرفة والمشاريع، وتُظهر فجوات الأدلة عندما لا تكفي المكتبة للبدء.
- إضافة اختبار يغطي اكتمال عقد المشروع وتتبع استهلاك العبقري له عبر المقرر والدرس والوحدة المعرفية والمشروع.
- تصحيح مسار الأمن السيبراني ليضم تقييم الاختراق وكتابة التقارير ضمن هيكل 24 مقررًا.

**المتبقي في هذه المرحلة:**
- تدقيق المحتوى التخصصي لكل مقرر ودرس بدل الاعتماد على العمق العام عند الحالات غير المغطاة بمخطط متخصص.
- تعميق مخططات التخصصات المتبقية حتى لا تكون المشاريع العامة مجرد غلاف شكلي، مع إبقاء المحتوى الكانوني داخل المكتبة نفسها.
- ربط المتطلبات السابقة والمفاهيم والمهارات والمشاريع على مستوى أعمق بين المقررات.
- قياس قابلية بناء أنظمة متعددة التخصصات من مجموعة مقررات، وليس من مقرر منفرد فقط.
- اعتماد نتائج التدقيق قبل اعتبار مرحلة التعميق مكتملة.

**قاعدة مستقبلية مثبتة:** أي إضافة جديدة لمتطلبات قابلية البناء أو آلية استهلاك المكتبة من العبقري تُسجل هنا أولًا، ثم تُنفذ داخل المكونات القائمة دون إنشاء مسار معرفي موازٍ.
