# TOFAN AL-ABQARI — Engineering Intelligence Architecture

العبقري طوفان طبقة ذكاء هندسي فوق المكتبة الأكاديمية الحالية، ولا ينشئ كتالوجاً أكاديمياً موازياً.

## Runtime pipeline
1. Project idea
2. Requirements analysis
3. Discipline identification
4. Academic-library retrieval
5. Skill identification
6. Knowledge-gap detection
7. Engineering plan
8. Software implementation
9. Computer simulation
10. Testing and error analysis
11. Correction and re-test
12. Experience and skill update

## Knowledge boundary
The existing AcademicCatalog is the academic source. AcademicKnowledgeEngine indexes lesson content, terms, outcomes, concepts and skills. External model providers are not treated as a replacement for the academic library.

## Computer-first boundary
The first engineering stage is software-first: architecture, code, simulation, automated tests and reports. Physical component classes are reported separately for later real-world implementation; simulation is not treated as physical certification.

## Next layers
persistent concept/skill graph -> prerequisite validation -> project knowledge-gap learning loop -> controlled code workspace/execution -> simulation adapters -> test/evaluation engine -> experience store -> project UI.

All layers must reuse the existing domain/application/data boundaries and must not create a duplicate academic catalog.
